# RAG 知识库问答系统 —— 改进建议文档

> 依据：测试工程师反馈（4 项问题）
> 日期：2026-08-31
> 状态：**已实施**（2026-08-31 四项全部完成，实施记录见文末第五节）

---

## 一、问题清单与现状分析

### 问题 1：无异步任务队列，上传大文档同步阻塞

**现状**：上传文档时，解析 → 切块 → 计算向量 → 写入 FAISS 全部在请求内同步完成。文档较大时，前端长时间等待，体验差，且存在请求超时风险。

**影响**：大文件上传体验差；答辩演示时若选大文件会有明显等待。

**改进方案**：

| 方案 | 做法 | 优缺点 |
|---|---|---|
| A. 轻量后台任务（**推荐**） | 用 FastAPI 内置 BackgroundTasks：上传接口立即返回"已接收"，向量化后台执行，文档状态字段（处理中/完成/失败）供前端轮询展示 | ✅ 无新依赖，改动小 ✅ 答辩易讲 ❌ 进程重启时未完成任务会丢 |
| B. Celery + Redis | 引入独立任务队列与 Worker 进程 | ✅ 生产级 ❌ 本机无 Redis，Windows 安装折腾；新增中间件增加演示故障点；毕设性价比低 |

**结论**：毕设阶段采用方案 A，论文/答辩中说明"生产环境可平滑升级为 Celery + Redis"。

### 问题 2：登录限流为单进程内存实现

**现状**：登录失败计数存于进程内存（`app/core/rate_limit.py` 的 `LoginRateLimiter`）。后端重启后计数清零；若部署多 worker，各进程计数互不共享。

**影响**：重启后端即可绕过限流；多进程部署时防线形同虚设。

**改进方案（推荐）**：将失败计数迁移到已有的 SQLite 数据库（新增一张限流记录表：标识、失败次数、首次失败时间、锁定到期时间）。无需引入新组件，重启不丢、多进程共享。

**备选**：答辩保持单进程部署，文档注明局限（工作量最小，但不如直接修复）。

### 问题 3：缺少端到端自动化测试

**现状**：现有测试覆盖单元层与接口层（`backend/tests/`），但没有覆盖"打开网页 → 登录 → 上传 → 提问 → 查看答案与引用"全链路的自动化测试。

**影响**：前端 + 后端联动的回归只能靠人工点验；答辩少一个"自动化测试"亮点。

**改进方案（可选）**：用 Playwright 编写 1~3 条端到端脚本，覆盖核心链路：
1. 登录成功 / 失败流
2. 创建知识库 → 上传文档 → 提问 → 断言答案与引用来源出现

**结论**：锦上添花项，答辩时间充裕再做；时间紧张可只做第 2 条撑场面。

### 问题 4：`datetime.utcnow()` 弃用警告

**现状**：`app/routes/auth.py` 中存在 2 处 `datetime.utcnow()`，Python 输出 DeprecationWarning，不影响运行。

**影响**：无功能影响；演示时控制台有红色警告，观感不佳。

**改进方案**：替换为 `datetime.now(timezone.utc)`（涉及字段为 SQLAlchemy DateTime 时需注意时区兼容，或继续使用 naive UTC 但用新写法生成）。改动极小。

## 二、优先级与建议排期

| 优先级 | 问题 | 预估工作量 | 建议 |
|---|---|---|---|
| 🔴 高 | ④ utcnow 弃用警告 | ~5 分钟 | 必做，顺手清掉 |
| 🟡 中 | ② 限流持久化到 SQLite | ~30 分钟 | 建议做，回答"多进程怎么办"更有底气 |
| 🟡 中 | ① 后台向量化（轻量版） | 1~2 小时 | 建议做，体验提升明显 |
| 🟢 低 | ③ 端到端自动化测试 | 半天 | 有余力再做 |

> 四项均为"更完善"级别优化，非"系统故障"级别硬伤——全部不做系统也能正常运行答辩。

---

## 三、答辩话术参考（如被问到）

- **关于任务队列**："当前采用 FastAPI 后台任务实现异步向量化，避免上传阻塞；生产环境可平滑升级为 Celery + Redis 分布式任务队列，接口层无需改动。"
- **关于限流**："登录限流计数已持久化到数据库，重启与多进程部署下依然生效。"
- **关于测试**："单元与接口测试覆盖核心逻辑，另配有 Playwright 端到端脚本验证关键业务链路。"

---

## 四、实施与验收要求（动手时遵循）

1. 改动前先跑一遍现有测试，确认基线全绿。
2. 改完后再跑测试 + 手动验证全链路：登录 → 建会话 → 流式问答 → 引用来源 → 上传文档。
3. 后端改动后需手动重启 `run.py`（本机 uvicorn watchfiles 不稳定）。
4. 数据/向量库文件保持在 `db_data/` 子目录，避免提权写操作污染。
